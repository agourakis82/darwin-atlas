# Darwin Operator Symmetry Atlas — Scientific Specification

**Specification version:** 0.1.0  
**Status:** normative draft for the pilot  
**Last updated:** 2026-07-30

## 1. Scientific objective

Darwin Operator Symmetry Atlas (DOSA) will measure distinct, explicitly named
forms of sequence symmetry in a frozen cohort of bacterial RefSeq replicons.
It is not a generic database of palindromes or inverted repeats. The scientific
contribution is an operator-resolved atlas that separates:

1. positional reversal and reverse-complement similarity;
2. reverse-complement symmetry of k-mer composition;
3. rotational periodicity;
4. equivalence caused only by the arbitrary origin and strand used to represent
   a circular double-stranded replicon.

Every released observation must be traceable to an immutable input manifest,
the Sounio producer executable, the analysis parameters, and an independent
Julia validation report.

## 2. Normative language and evidence states

The words **MUST**, **MUST NOT**, **SHOULD**, and **MAY** are normative.

Three evidence states MUST remain distinct:

- **COMPILES:** the Sounio compiler accepted a source file.
- **EXECUTES:** an identified executable ran and returned the expected process
  status on a named fixture.
- **SCIENTIFICALLY VALIDATED:** persisted Sounio artifacts passed schema,
  provenance, metamorphic, and independent Julia differential checks.

Compilation alone MUST NOT be reported as execution or scientific validation.

## 3. Implementation authority

- **Sounio is the sole canonical scientific producer.** It parses the normalized
  FASTA input and produces all release-candidate observations and receipts.
- **Julia is an independent validator.** It reads the same immutable inputs and
  the persisted Sounio outputs, recomputes a deterministic validation sample,
  and emits a comparison report.
- Julia MUST NOT silently replace Sounio in a production, release, or
  cross-validation command.
- Julia and Sounio SHOULD NOT share an FFI implementation in the publication
  gate. File-level comparison is required to preserve implementation
  independence.
- NCBI Datasets CLI and a thin shell/Make orchestration layer MAY acquire and
  checksum inputs. They do not compute scientific observations.

If Sounio is unavailable, production fails. If Julia is unavailable, Sounio may
produce development artifacts, but the release validation state remains red.

## 4. Alphabet and input policy

Let the canonical alphabet be `Sigma = {A,C,G,T}` with Watson-Crick complement
`K(A)=T`, `K(T)=A`, `K(C)=G`, and `K(G)=C`.

Input readers MUST preserve IUPAC ambiguity symbols. They MUST NOT coerce an
ambiguous symbol such as `N` to a canonical base. Each metric MUST declare one
of these policies:

- `canonical_only`: reject an analysis unit containing ambiguity;
- `masked`: omit affected positions or k-mers and report the effective count;
- `iupac_compatible`: use a separately specified ambiguity-aware definition.

The pilot uses `canonical_only` for positional metrics and `masked` for k-mer
composition. Every exclusion MUST carry a machine-readable reason code.

The canonical reader MUST process more than one FASTA record without requiring
the complete input file or complete replicon set in memory. Lowercase symbols
MUST normalize to their uppercase IUPAC identity; `CRLF` and `LF` line endings
MUST be accepted. Sequence bytes outside `ACGTRYSWKMBDHVN` (case-insensitive)
MUST be rejected rather than silently deleted or coerced.

Parser failures use stable identifiers: `OPEN_FAILED`, `READ_FAILED`,
`SEQUENCE_BEFORE_HEADER`, `EMPTY_HEADER`, `EMPTY_SEQUENCE`, `INVALID_SYMBOL`,
and `NO_RECORDS`. The failure artifact MUST include the zero-based input byte
offset, offending byte when one exists, and current one-based record index (or
zero before the first header).

## 5. Operators and group actions

For a sequence `w = w_0 ... w_(n-1)`:

- identity: `(I w)_i = w_i`;
- left shift: `(S^k w)_i = w_((i+k) mod n)`;
- reversal: `(R w)_i = w_(n-1-i)`;
- complement: `(K w)_i = K(w_i)`;
- reverse complement: `RC = R K = K R`.

The implementation MUST distinguish the following actions:

| Identifier | Elements | Structure | Use |
|---|---|---|---|
| `v4_strand` | `{I,R,K,RC}` | Klein four group `V4` | operator identities only |
| `dn_reverse` | `{S^k, S^k R}` | `D_n`, order `2n` | reversal/periodicity analysis |
| `dn_rc` | `{S^k, S^k RC}` | `D_n`, order `2n` | circular dsDNA representation |
| `dn_extended` | generated by `S,R,K` | `D_n x C2`, order `4n` | optional algebraic analysis |

`{I,R,K,RC}` MUST NOT be called `D4` without explicitly stating a convention
that defines `D4` as the order-four dihedral group.

## 6. Analysis domains

### 6.1 Linear local windows

Windows are half-open intervals `[start,end)` in the submitted replicon
orientation. They MUST NOT wrap around the end of the replicon. Positional
window metrics use `R` and `RC`; cyclic shifts are not part of their primary
biological interpretation.

### 6.2 Whole circular replicons

For an assembly-declared circular replicon, origin and strand are representation
choices. The canonical representation is

`canon_rc(w) = lexicographic_min({S^k w, S^k RC(w) | 0 <= k < n})`.

This canonicalization is an identity/deduplication operation, not itself a
biological symmetry score.

### 6.3 Whole linear or topology-unknown replicons

No cyclic wraparound or rotation equivalence is allowed. Unknown topology MUST
remain unknown rather than being inferred from sequence length or molecule type.

## 7. Primary metrics

### 7.1 Positional metrics

For a canonical linear analysis unit of length `L > 0`:

- `delta_R(w) = H(w,Rw)/L`;
- `delta_RC(w) = H(w,RCw)/L`;
- `fixed_R(w) = [w = Rw]`;
- `fixed_RC(w) = [w = RCw]`.

For canonical DNA, `fixed_RC` MUST be false when `L` is odd. Direct positional
`H(w,Kw)/L` is identically one and MUST NOT be published as an informative
metric.

### 7.2 Reverse-complement k-mer composition

Let `c_w(u)` be the count of canonical k-mer `u` in an analysis unit, after the
declared ambiguity policy. For `T` equal to `R` or `RC`, partition k-mers into
unordered pairs `{u,T(u)}` and define

`operator_kmer_imbalance_(T,k)(w) = sum_pairs |c_w(u)-c_w(T(u))| / sum_pairs (c_w(u)+c_w(T(u)))`.

Self-transformed k-mers contribute zero to the numerator and their count once
to the denominator. The primary compositional measure is
`rc_kmer_imbalance_k`; `reverse_kmer_imbalance_k` is its matched comparator.
The effective number of valid k-mers MUST be emitted.

The pilot SHOULD evaluate `k=1..8`, subject to a predeclared minimum expected
count. Sparse combinations MUST be marked unavailable, not filled with zero.

### 7.3 Periodicity

- `minimal_period(w)` is the least positive `p` such that `S^p w = w` for a
  circular analysis unit, or `L` if no smaller period exists.
- `cyclic_match_k(w) = 1 - H(w,S^k w)/L` MAY be emitted for predeclared lags.

Searching all lags and retaining only the minimum or maximum is exploratory and
MUST be calibrated against an identical search on the null replicates.

### 7.4 Secondary exploratory metrics

Minimum distance over operator families MAY be retained under an
`experimental_` prefix. The exact transform family, number of candidates, null
distribution, and standardized effect MUST accompany it. It is not a primary
atlas endpoint in specification 0.1.0.

Quaternion and dicyclic lifts are compiler/algebra conformance experiments.
They MUST NOT appear in the primary biological tables or novelty claim without
a separately reviewed biological hypothesis.

## 8. Cohorts and acquisition

Two frozen cohorts are planned:

- `core`: complete RefSeq bacterial reference assemblies, used for the primary
  cross-species atlas;
- `expansion`: all complete RefSeq bacterial assemblies, used for within-species
  and strain-level analyses.

The cohort is defined by an accession-version manifest, not by a mutable taxon
query. The manifest MUST record the NCBI Datasets version, query filters,
retrieval time, assembly accession including version, included files, and NCBI
package checksums. Reference and expansion releases MUST never be pooled without
an explicit sampling/weighting model.

## 9. Null models and inference

Each inferential metric MUST be evaluated against:

1. a primary dinucleotide-preserving shuffle or fitted first-order Markov null;
2. a mononucleotide-preserving shuffle as a diagnostic sensitivity analysis.

Seeds MUST be deterministically derived from the run parameter hash, stable
replicon identifier, window coordinates, metric identifier, and replicate index.
The derivation algorithm is part of the parameter artifact.

ADR-0003 fixes one engineering candidate for the dinucleotide shuffle: a
fixed-endpoint Euler trail over the directed dinucleotide multigraph, with a
Wilson loop-erased arborescence, rejection-sampled bounded choices, and
deterministic replicate substreams. That executable fixture does not select the
pilot model or constitute inferential validation; ADR-0002 remains proposed.

Tests MUST be grouped into predeclared hypothesis families and corrected with
Benjamini-Hochberg FDR. Effect sizes and null quantiles MUST accompany p- and
q-values. Chromosomes and plasmids, circular and linear replicons, and the core
and expansion cohorts MUST be reported separately.

## 10. Predeclared pilot hypotheses

- **H1:** reverse-complement k-mer imbalance is lower than reversal-paired k-mer
  imbalance at matched `k`, window size, and null model.
- **H2:** in the subset with a predeclared, high-confidence replication-origin
  annotation, local reverse-complement imbalance varies with
  replication-relative coordinate after controlling for GC content and sequence
  complexity.
- **H3:** chromosomes and plasmids differ in their operator profiles after
  controlling for length, GC content, taxonomy, and sampling multiplicity.
- **H4 (exploratory):** unusually small positional `delta_RC` windows are
  enriched relative to dinucleotide-preserving nulls.

These are hypotheses, not established conclusions.

## 11. Canonical data products

### 11.1 `cohort_assemblies.jsonl` / Parquet

Required fields: `assembly_accession_version`, `taxid`, `organism_name`,
`refseq_category`, `assembly_level`, `retrieval_utc`, `datasets_version`,
`package_md5`, and `included`.

### 11.2 `atlas_replicons.jsonl` / Parquet

Required fields: assembly accession-version, sequence accession-version,
replicon class, declared topology, length, canonical/ambiguous base counts, GC
fraction, input hash, inclusion state, and exclusion reason.

### 11.3 `window_operator_profiles.jsonl` / Parquet

Required fields: stable replicon ID, zero-based half-open coordinates, window
length, ambiguity policy/effective count, `delta_R`, `delta_RC`, fixed flags,
k-mer imbalance fields, null summaries, p/q values, and metric version.

### 11.4 `replicon_operator_summary.jsonl` / Parquet

Required fields: stable replicon ID, representation domain, canonicalization
hash when applicable, minimal period or declared unavailability, aggregate
operator profiles, and metric version.

### 11.5 `excluded_records.jsonl`

Every excluded assembly, replicon, window, or metric with a stable reason code
and enough coordinates/identifiers to reproduce the decision.

### 11.6 `run_receipt.json`

The receipt MUST validate against `schemas/run_receipt.schema.json`. A release
receipt binds the Sounio compiler and executable hashes, source commit, immutable
input manifest, parameters, output artifacts, commands, and Julia validation
report.

## 12. Validation contract

### 12.1 Metamorphic properties

Sounio and Julia MUST independently test at least:

- `R(R(w)) = w`, `K(K(w)) = w`, and `RC(RC(w)) = w`;
- `R(K(w)) = K(R(w))`;
- `S^n(w) = w` and `RC S RC(w) = S^-1(w)`;
- `GC(w) = GC(RC(w))`;
- whole-circular metrics are invariant to input origin and strand;
- odd canonical sequences are not `RC`-fixed;
- tiled fixtures have the declared minimal period;
- input record order does not change canonical sorted output or content hashes.

### 12.2 Differential validation

Julia MUST recompute all golden fixtures and a deterministic stratified sample
of persisted Sounio observations. The sample definition and hash MUST be in the
validation report. Discrete values require exact equality. Floating-point
tolerances are metric-specific and MUST be fixed in the parameter artifact;
`1e-12` is the default absolute tolerance for deterministic normalized counts.

Any mismatch blocks release. Absence of either implementation is not a pass.

## 13. Release gates

| Gate | Requirement |
|---|---|
| G0 | Clean source tree; atlas commit, Sounio commit, compiler path/version/SHA256 recorded |
| G1 | Executable Sounio unit, golden, and metamorphic fixtures pass |
| G2 | Frozen miniature NCBI fixture runs end to end through Sounio |
| G3 | Julia independently reproduces the deterministic validation sample |
| G4 | Schemas, accession versions, exclusions, parameters, and checksum closure validate |
| G5 | Pilot performance and memory receipts support the proposed cohort scale |
| G6 | Release bundle is immutable, licensed, DOI-ready, and contains a passing receipt |

A gate becomes stale whenever its bound source, compiler/executable, inputs,
parameters, or dependent artifact hash changes.

## 14. Current boundary

As of specification 0.1.0, the repository contains exploratory Julia code and
partial Sounio kernels. It does not yet contain a scientifically validated atlas
run. One positional fixture now reaches `EXECUTES` and exact Base-only Julia
differential agreement. A chunked, multi-record IUPAC FASTA fixture also reaches
`EXECUTES` and exact Julia differential agreement across valid and invalid
inputs. A parameterized frozen mini-pipeline fixture — versioned, checksummed
parameter artifacts (`parameters_k4.json` 4/4, `parameters_k8.json` 16/16)
rendered to a strict flat form and revalidated by the executable; two 16 bp
NCBI prefixes plus synthetic controls, associated with a metadata TSV,
windowed without overlap, scored with `delta_R`/`delta_RC`, with explicit
`AMBIGUOUS_WINDOW` and `PARTIAL_WINDOW` exclusions, and with masked k-mer
composition (`reverse_kmer_imbalance_k`/`rc_kmer_imbalance_k` as defined in
§7.2) for the full predeclared pilot range `k=1..8` with explicit per-k
unavailable reasons — reaches `EXECUTES` with deterministic JSONL (additive
schema 0.3.0) and byte-exact Base-only Julia agreement, including negative metadata
and negative parameter fixtures, under two independently written k-mer kernels
(simple reference and scale-oriented rolling table) required to agree byte for
byte. `min_kmer_effective_count=1` remains an executable-fixture parameter,
not the pilot threshold. The mononucleotide sensitivity fixture and the
ADR-0003 exact dinucleotide-preserving candidate now execute inside the frozen
window fixture under independent Julia differential checks, and both have
engineering U250 accelerator surfaces; neither is integrated into canonical
pilot products. The pilot
minimum expected count and final null parameters remain open under proposed
ADR-0002. These executable specifications do not elevate the absent full
cohort pipeline to `SCIENTIFICALLY_VALIDATED`. Successful parsing/code
generation by itself remains evidence only for `COMPILES`.

## 15. Change control

Changes to operator semantics, primary metrics, ambiguity policy, cohorts, null
models, hypothesis families, or release gates require a specification version
bump and an architecture decision record. Metric outputs MUST carry their
specification version so results from incompatible definitions cannot be merged.
